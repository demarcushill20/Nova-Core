# Dataset Policy

## Holdout Discipline

The train/test split is sacred. The optimizer:
- Trains on the train set
- Validates on the dev set (optional)
- Evaluates final candidates on the test set ONLY ONCE per candidate
- NEVER uses test results to guide mutation

The improvement model sees only blinded (train-only) history. Test scores
are recorded for decision-making but never fed back into the mutation prompt.

## Minimum Requirements

| Split | Min Records | Purpose |
|-------|-------------|---------|
| train.jsonl | 6 (3+/3-) | Mutation guidance |
| dev.jsonl | 0 (optional) | Hyperparameter tuning |
| test.jsonl | 4 (2+/2-) | Final evaluation |
| hard_negatives.jsonl | 0 (recommended) | Anti-broadening |

## Quality Rules

1. **No duplicates** within any split
2. **No leakage** across train/dev/test splits
3. **Reasonable balance** — at least 20% of each class in train/test
4. **Hard negatives** must reference real neighbor skills
5. **Valid schema** — all records match `schemas/eval_record.schema.json`
6. **No synthetic inflation** — each query should represent a real user intent

## Dataset Evolution

Datasets can grow over time but must follow these rules:
- New records go to train set first (test set is stable)
- Test set changes require re-baselining all affected skills
- Hard negatives should be added when new conflicts are discovered
- All changes to datasets should be committed with clear reasoning

## Global Datasets

### smoke_test.jsonl
One positive query per eligible skill. Used for ecosystem-wide regression.
Must be updated when new skills become eligible.

### overlap_pairs.json
Defines the boundary between confusable skill pairs. Each pair has:
- Boundary description (human-readable)
- Test queries with expected skill assignment

### paraphrase_sets.jsonl
Groups of semantically equivalent queries. Used to measure consistency.

## Dataset Generation

Datasets may be:
1. Hand-authored (highest quality)
2. Generated by Claude and human-reviewed
3. Extracted from historical usage logs (if available)

Option 1 is preferred. Option 2 is acceptable with review. Option 3 requires
deduplication and balance checking.
